책갈피(독서 기록 웹앱) · 나 분담 · 2026-03-02 ~ 03-06 · PR #12 병합
책 검색 · 등록과 독서 기록 저장 두 묶음을 마침. 책 정보 출처와 기록 저장 방식은 실측을 거쳐 정했고, 처음 가정 두 가지를 버림.
  • 책 검색은 공개 도서 API 두 곳을 비교해, 한국어 책 적중이 높은 쪽으로 바꿈.
  • 독서 기록은 쪽수만 저장하던 것을 날짜별 기록으로 바꿔, 하루 읽은 양을 볼 수 있게 함.
  • 같은 책을 두 번 등록하지 않도록 ISBN으로 막고, ISBN 없는 책은 제목 · 저자로 확인함.

1. 무엇을 만들었나

1.1 만드는 제품

혼자 읽는 책을 기록하는 웹앱임. 읽을 책을 검색해 서재에 넣고, 읽은 날마다 쪽수를 적으면 얼마나 읽었는지와 다 읽을 날을 보여 줌.

제품이 지켜야 할 약속 가운데 이번 작업과 직접 관련된 것은 다음과 같음.

  • 같은 책이 두 번 들어가지 않음: 서재에 같은 책이 둘이면 기록이 나뉘어 진행률이 틀어짐.
  • 기록은 지워지지 않음: 쪽수를 고쳐도 이전 기록이 남아야 날짜별 독서량을 다시 계산할 수 있음.

1.2 전체 워크플로와 이번 작업의 위치

사용자가 화면에서 책을 찾으면 API가 서비스를 부르고, 서비스는 외부 도서 API와 저장소를 씀. 화면은 동료가, API와 서비스 · 저장은 내가 맡음.

① 책 검색 · 등록

역할읽을 책을 찾아 내 서재에 넣는 입구. 서재에 들어간 책만 기록할 수 있음.
동작제목이나 저자로 검색하면 외부 도서 API 결과를 10건까지 보여 줌. 하나를 고르면 이미 서재에 있는지 확인한 뒤, 없을 때만 책과 첫 기록(0쪽)을 함께 저장함.
특징
  • 같은 책 확인은 ISBN으로 함. ISBN이 없는 오래된 책은 제목과 저자가 모두 같을 때 같은 책으로 봄.
  • 외부 API 응답은 하루 동안 저장해 둠. 같은 검색어를 다시 부르지 않아 하루 호출 한도(1,000회)를 넘지 않음.
  • 책과 첫 기록은 한 트랜잭션으로 저장해, 책만 있고 기록이 없는 상태가 생기지 않음.

② 독서 기록 저장

역할책마다 언제 몇 쪽까지 읽었는지 남기는 곳. 진행률과 다 읽을 날 계산의 바탕.
동작날짜와 쪽수를 적으면 새 기록 한 줄이 생김. 같은 날 다시 적으면 그날 마지막 기록이 그날의 값이 되고, 이전 줄은 지우지 않음.
특징
  • 기록은 덧붙이기만 함. 잘못 적은 쪽수를 고쳐도 이전 줄이 남아 날짜별 독서량을 다시 계산할 수 있음.
  • 쪽수가 책 전체 쪽수보다 크거나 이전 기록보다 작으면 저장하기 전에 묻음.

3. 주요 결정

3.1 책 정보는 어느 API에서 가져올까

문제처음에는 해외 도서 API를 쓰려 했음. 한국어 책 검색 결과가 비는 경우가 많았음.
검토한 안해외 도서 API · 국립중앙도서관 API · 두 곳을 차례로 부르기
근거한국어 책 30권으로 비교함. 해외 API 17권, 국립중앙도서관 28권 적중. 두 곳을 차례로 부르면 29권이지만 응답이 두 배 느림.
결론국립중앙도서관 API 하나. 못 찾은 책은 직접 입력으로 받음. 직접 입력이 한 달에 10건을 넘으면 두 곳 부르기를 다시 봄.

3.2 기록을 덮어쓸까, 덧붙일까

문제처음에는 책마다 "지금 쪽수" 하나만 저장했음. 날짜별로 얼마나 읽었는지 알 수 없었음.
검토한 안지금 쪽수만 덮어쓰기 · 날짜마다 한 줄 덮어쓰기 · 적을 때마다 한 줄 덧붙이기
근거하루 여러 번 고치는 경우가 실제 사용 기록의 20%. 덮어쓰면 고친 이유를 되짚을 수 없음. 덧붙이기도 책 한 권에 기록 200줄 수준이라 저장 부담이 작음.
결론덧붙이기. 그날의 값은 그날 마지막 줄로 계산함.

3.3 그 밖의 결정

항목결론과 이유
외부 API 응답 저장 기간하루. 책 정보는 거의 바뀌지 않고, 하루 호출 한도를 넉넉히 지킴.
ISBN 없는 책제목과 저자가 모두 같을 때만 같은 책. 제목만 같으면 다른 판일 수 있음.

4. 검증 중 발견한 문제

  • 저장의 틈: 책과 첫 기록을 따로 저장하자, 그 사이에서 실패하면 기록 없는 책이 남았음. 한 트랜잭션으로 묶음.
  • 시간대: 밤 11시 이후 기록이 다음 날로 잡혔음. 날짜를 서버 시간이 아니라 사용자 시간대로 계산하게 고침.
