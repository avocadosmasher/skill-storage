# 수정 요청을 스킬의 작성 기준으로 편입

현재 세션의 사용자가 저자다. 수정 요청에서 이번 원고의 조치와 다음 글에도 쓸 기준을 구분하라. 스킬 지속 개선을 요청받은 작업에서는 분석 메모에 그치지 않고 재사용할 기준을 이 스킬의 실제 지시문에 반영하라.

## 수정 이유를 찾고 현재 원고를 고쳐라

- 요청·대체 문장과 수정 전 원고를 가능한 범위에서 보존하고 차이를 확인하라. 원본이 없으면 비교했다고 주장하지 마라. 수정본 대조는 [composition.md](composition.md)의 사용자 수정본 절을 따른다.
- 사용자가 밝힌 이유를 우선하라. 이유가 없으면 의도를 잠정적으로 해석하되 확정된 선호로 편입하지 마라. 집필 방향이 크게 갈리는 경우에만 필요한 질문을 하라.
- 단어·문장 리듬, 문단 연결·도입 설계, 정보 배치·글의 범위 중 문제의 단위를 찾아라. 배경이 빠진 도입을 접속어나 말끝만 바꾸어 해결했다고 하지 마라.
- 요청 부분과 연결된 예고·참조·마무리를 고치고, 같은 문제가 다른 부분에도 있는지 살펴라. 부분 수정 요청을 글 전체의 관점 변경으로 확대하지 마라.

## 재사용할 기준을 해당 스킬 문서에 편입하라

| 수정의 성격 | 반영할 곳 | 판단 기준 |
| --- | --- | --- |
| 사실·오탈자·이번 글만의 선택 | 현재 원고와 필요한 작업 기록 | 날짜 정정이나 공지 한 편의 분량 제한을 스킬의 문체 규칙으로 만들지 않음 |
| 지속적인 말투·도입·설명 호흡 | `references/voice.md`의 해당 기준 | 앞으로의 글에도 원하는 방식이 명시됐거나 사용자가 지속 기준으로 확인한 경우 |
| 소제목·범위·정보 배치·설명 방식 | `references/composition.md`의 해당 기준 | 같은 판단을 다음 글의 구성에도 재사용할 수 있는 경우 |
| 집필·검토·피드백 처리 절차 | `SKILL.md` 또는 이 문서 | 특정 예문 대신 작업의 판단 절차를 바꾸어야 하는 경우 |

- 명시적인 앞으로도 요청은 한 번이어도 기준으로 편입할 수 있다. 반복된 교정에서 추정한 취향은 작업 메모에 잠정 상태로 남기고 확정 지시문으로 적용하지 마라. 중요한 차이만 확인하라.
- 선택한 사용자 문장의 표면을 그대로 복제하지 말고, 그 문장이 해결한 문제와 적용 조건을 기준으로 써라. 경험 소개 글의 도입을 고쳤다고 모든 공지·실습·문제 해결 글에 같은 순서를 강제하지 마라.
- 현재 기준을 먼저 읽고 해당 항목을 고쳐라. 같은 규칙을 여러 문서에 반복 추가하거나 교정마다 새 파일을 만들지 마라. 기존 기준과 충돌하면 대체·한정하고 모순되는 활성 규칙을 함께 남기지 마라.
- 작업 보고의 개조식 요청은 본문 문체로 편입하지 마라. 새로운 사실·미확인 동향·사용자의 예시 속 오탈자도 문체 기준이나 검증된 경험으로 만들지 마라.
- 규칙은 이미 충분한데 원고가 지키지 못했다면 원고를 바로잡고 기존 검토를 수행하라. 같은 금지 문장을 더하는 것으로 개선을 대신하지 마라.

예: 도입이 갑작스럽다는 교정이 배경과 개인의 선택을 연결하라는 요청이라면, 원고의 도입을 고치고 `voice.md`의 도입 기준도 보완한다. 다음 글에서는 별도 교정 로그를 전달받지 않아도 스킬의 기준을 읽어 그 흐름을 사용해야 한다.

## 수정 가능한 원본에서 검증하라

- 스킬 지속 개선 요청이 있으면 허용된 범위의 편입을 이어가고 같은 허락을 매 교정마다 다시 묻지 마라. 원고만 수정하도록 맡긴 작업에서 공유 원본 수정까지 허가받았다고 확대하지 마라.
- 이 스킬의 수정 가능한 원본 저장소나 사용자가 관리하는 사본을 고쳐라. 설치된 플러그인 캐시는 업데이트로 사라질 수 있으므로 직접 고치지 마라. 다른 설치자의 사본이나 공유 원격 저장소는 별도 작업 대상이다.
- 원본을 고칠 수 없으면 적용할 변경안이나 수정 가능한 스킬 사본을 준비하고, 아직 실제 사용 스킬에 반영하지 못했다고 밝혀라. 외부 선호 메모에 저장한 상태를 스킬 편입 완료로 보고하지 마라.
- 일반 집필은 이 스킬의 `voice.md`와 필요한 `composition.md`를 읽어 개선된 기준을 사용한다. 외부 교정 로그는 변경 근거이며, 스킬의 활성 기준을 대신하지 않는다. 다른 환경에서도 사용할 때는 수정한 스킬 버전을 함께 전달해야 한다.
- 원본 저장소의 설계·검증·승인 절차를 따르라. 링크·형식과 기존 기준의 충돌을 확인하고, 관련 사례에 적용해 의도한 변화와 일회성 요청의 범위가 유지되는지 확인하라. 새 세션에서 실행하지 않았다면 세션 간 재현을 검증했다고 하지 마라.
- 변경 이유와 검증 결과는 기존 작업 기록에 짧게 남겨라. 최종 사용자에게는 원고에서 바꾼 점과 스킬에 편입한 기준을 설명하라. 커밋·푸시·배포는 해당 저장소의 승인 절차를 따른다.
- 공유할 스킬에는 작성 기준만 남기고 비공개 원고·메일·프로젝트 자료를 복사하지 마라. 다운로드한 사용자는 이 기본 프로필을 출발점으로 자기 사본을 개선할 수 있다.
