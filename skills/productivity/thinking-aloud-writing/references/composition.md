# 전개와 설명 요소 조합

## 중심 전개를 선택하라

아래 순서는 출발점으로 사용하라. 소제목으로 복사하거나 모든 항목을 채우지 마라. 독자 목표와 자료에 따라 합치거나 생략하라. 주된 전개를 하나 정하고 다른 방식의 요소를 필요한 곳에 더하라.

| 전개 | 선택할 상황 | 설명 순서 |
|---|---|---|
| 원리 탐구 | 기술이 왜 필요한지 이해시키기 | 핵심 질문 → 필요한 배경 → 기존 한계 → 해결 원리 → 작동 과정 → 비용과 범위 |
| 사용기·문제 해결 | 특정 환경의 불편과 해결 전달 | 환경과 실제 문제 → 원인 또는 후보 → 선택 이유 → 조치 → 확인한 결과 → 조건과 남은 문제 |
| 분석·개선 | 도구·설계·지시문 검토 | 목적 → 기존 방식과 강점 → 한계 → 근거와 대안 → 변경 내용과 이유 → 대가와 한계 |
| 실습 해설 | 코드나 구현 흐름 이해 | 목표와 전체 흐름 → 입력 → 핵심 처리와 이유 → 출력 → 전체 연결 → 실무와의 차이 |
| 프로젝트 소개 | 만든 제품이나 도구의 목적과 쓰임 전달 | 해결할 문제 → 사용 흐름과 주요 기능 → 필요한 구조 설명 → 확인 가능한 결과와 범위 |
| 개발 회고 | 개발 중 선택과 배운 점 전달 | 목표와 제약 → 검토한 방법 → 결정과 이유 → 실제 진행·변경 → 결과와 배운 점 |

역사 순서는 현재 설계가 나온 이유를 이해하는 데 필요할 때 사용하라. 연도와 제품명을 모으는 것이 목표가 되지 않게 하라. 사용자 경험이 없는 자료는 원리 탐구·분석·실습으로 충분히 구성할 수 있다고 판단하라.

개발 회고에 필요한 경험이 빠졌다면 먼저 기록을 찾고 사용자에게 인터뷰하라. 사용자가 경험을 제공하지 않거나 기억하지 못하면 확인 가능한 구현 해설 등으로 범위를 조정하라. 저장소의 폴더·함수 목록을 그대로 글의 목차로 만들지 마라.

## 설명 요소를 고르고 배치하라

| 요소 | 넣는 기준 | 담을 내용 |
|---|---|---|
| 실제 계기 | 자료로 확인된 사용자 경험이 이해를 도움 | 환경, 하려던 일, 막힌 점 |
| 핵심 질문 | 뒤 설명을 읽을 이유가 필요함 | 해결되지 않은 질문과 답할 범위 |
| 정의와 재설명 | 새 용어가 이후 논리의 전제임 | 용어, 실제 대상, 누가 무엇을 하는지 |
| 오해 교정 | 실제 오해 또는 독자에게 혼동 가능성 | 처음 해석과 올바른 관계; 저자의 오해로 꾸미지 말 것 |
| 작동 과정 | 원인과 결과 사이의 단계가 필요함 | 입력, 실행 주체, 상태 변화, 출력 |
| 비교와 선택 | 대안 중 선택 이유가 중요함 | 공통 기준, 장점, 비용, 조건 |
| 코드·예시·그림 | 동작이나 관계가 더 분명해짐 | 자료로 무엇을 확인하는지와 읽는 방법 |
| 결과와 한계 | 효과 주장 또는 범위 마무리 | 확인 결과, 미확인 범위, 남는 문제 |
| 보충·후속 | 유용하지만 현재 답에 필수는 아님 | 배경, 세부 명령어, 예외, 후속 질문 |

개인 반응과 유머는 필수 절로 만들지 말고 설명 사이에 자연스럽게 두어라. 결론은 읽기 전과 비교해 이해가 어떻게 바뀌었는지 정리하라. 실제 후속 주제가 없으면 다음 편을 예고하지 마라.

## 질문과 자료 요청을 선별하라

이미 확인한 내용을 묻지 마라. 아래에서 구조나 사실성을 바꾸는 항목만 선택하라.

| 빈틈 | 질문하거나 확보할 정보 | 영향 |
|---|---|---|
| 목적 | 원리 이해, 절차 재현, 개선 판단 중 필요한 결과 | 전개와 깊이 |
| 독자 | 이번 주제에서 이미 아는 배경 | 선수지식과 예시 |
| 계기 | 문제를 겪은 환경과 하려던 일 | 경험형 도입의 사실성 |
| 선택 이유 | 다른 방법을 검토했는가, 무엇 때문에 선택했는가 | 근거; 없으면 사실 중심 비교 |
| 결과 | 출력·로그·관찰과 측정 조건 | 결과 표현의 범위 |
| 설명의 연결 | 전제에 대한 출처 확인, 필요한 실험 자료 | 인과 설명과 주장 강도 |

요청할 자료는 특정 출력·화면·로그 구간처럼 좁혀라. 필요하지 않은 전체 시스템 정보나 민감한 원본을 요구하지 마라. 자료 없이 쓸 수 있는 구간과 자료가 있어야 쓸 수 있는 주장을 나눠라.

## 응답을 조절하라

- 자료를 처음 받으면 목표, 제안하는 구성과 배치 이유, 꼭 필요한 질문을 제시하라. 자료 전체를 장황하게 되풀이하지 마라.
- 자료가 충분하고 집필 요청이 분명하면 구성 이유를 짧게 밝힌 뒤 요청 범위를 작성하라. 질문은 필수 절차가 아니다.
- 답변을 받으면 달라진 부분과 다음 초안을 제시하라. 모든 기획을 다시 설명하거나 승인 의식을 추가하지 마라.
- 새 사실로 구조가 맞지 않으면 이유와 영향 범위를 밝히고 수정하라. 처음 목차를 유지하려고 사실을 끼워 맞추지 마라.
- 문체 교정을 현재 초안과 다음 절에 반영하라. 한 문장 교정을 모든 글의 절대 금지 규칙으로 과잉 일반화하지 마라.
