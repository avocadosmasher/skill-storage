# 보고 형식

## 공통 규칙

개조식·두괄식으로 쓴다. 결론을 가장 먼저 말하고, 같은 사실을 두 번 말하지 않는다.
"이 규칙에 따라 멈춥니다" 같이 스킬 규칙을 인용하는 메타 설명은 쓰지 않는다.
항목이 둘 이상이면 한 문장에 늘어놓지 않고 번호 목록(1. 2. 3. ...)으로 쓴다.
"판정 필요: A, B"처럼 라벨 뒤에 쉼표로 잇는 것도 한 줄 나열이다.
그 아래 하위 목록이 필요하면 번호 대신 bullet(•)을 쓴다. 줄 안에서 구분이 필요해도
em dash(긴 줄표)로 잇지 않는다: 쟁점과 설명은 "선택:", "버린 대안:"처럼 이름 붙은 하위 항목으로
나누고, 화살표(→)는 조작과 그 결과처럼 방향이 있는 짝에만 쓴다.

## 정지 보고의 순서

1. **결론**: 끝난 일과 지금 필요한 판정. 여러 개면 목록으로.
2. **자동 진행 내역**: 마지막 정지 보고 이후 묻지 않고 진행한 단위. 없으면 뺀다.
   ```
   자동 진행 3건
   1. A02 가입 API: 요청 검증과 저장 (사유: 계획대로, 자동 검사로 증명 / 커밋 1a2b3c4)
   2. A04 로그인 API: 비밀번호 대조 (사유: 계획대로 / 커밋 5d6e7f8)
   3. A04a 오류 응답 형식 통일 (사유: 동작 동일한 리팩터링 / 커밋 9a0b1c2)
   ```
   이의가 있으면 사용자는 ID만 말하면 된다. 그 단위를 다시 연다.
3. **판단 재료** (결정 보고) 또는 **확인 방법** (확인 보고). 둘 다 필요하면 둘 다 쓴다.
4. **자동 검사**: 돌린 검사마다 통과·실패를 목록으로, 돌리지 않은 범위와 이유.
5. **판정 요청**: "직접 확인 후 '통과' 또는 '수정: [문제와 원하는 변경]'으로 알려주세요."

## 결정 보고: 판단 재료

쟁점마다 하위 항목으로 나눈다.

- 선택: 고른 안
- 버린 대안: 검토했지만 버린 안과 이유
- trade-off: 이 선택으로 가능해지는 것, 안 되는 것, 미룬 것

코드가 어떻게 짜였는지가 아니라 왜 이 방향을 골랐는지를 쓴다.
pre-commit이 보호 대상 변경으로 막은 경우, 걸린 파일과 이유(보호 경로, 기존 테스트 변경 등)를 결론에 쓴다.

## 확인 보고: 확인 방법

- 해볼 흐름을 번호별로 "조작 → 기대 결과" 짝으로 쓴다.
- **이번 묶음에서 바뀐 구조**: 새로 생긴 모듈·데이터·흐름을 세 줄 이내로. 사용자가 시스템을 계속 이해하게 하려는 것이다.
- 사용자가 직접 실행할 수 없는 환경이면 이유와 확인 시점·장소를 명시한다.

## 진행 중 한 줄 알림

자동 단위를 마칠 때는 멈추지 않고 한 줄만 남긴다.

```
A02 자동 진행: 가입 API 요청 검증 (커밋 1a2b3c4)
```

예산 때문에 멈출 때도 묻지 않고 알린다.

```
[예산] 이번 세션 단위 10개 (대리 지표: 단위 수) → STATUS.md 인계 후 정지 (새 세션 권장)
인계: 다음 할 일 A07, 확인 대기 없음
```

## 시각 정보

글보다 빨리 읽히는 경우에만 쓴다.

| 상황 | 표현 |
| --- | --- |
| 대안 2개 이상을 기준 2개 이상으로 비교 | 표 (행: 대안, 열: 기준). 아니면 bullet 하위 항목 |
| 하위 작업 여럿 중 일부만 끝남 | bullet 뒤에 `[x]`(완료)·`[ ]`(남음). dash로 시작하는 마크다운 체크리스트(`- [x]`)는 쓰지 않는다 |
| 수치 전후 비교 | `응답 시간: 320ms → 180ms` 한 줄. 지표가 여럿이면 표 |
| 배치·색·크기 같은 시각 결정 | 캡처 이미지 경로 (아래 1) |
| 구조·흐름 설명 | 다이어그램 (아래 2) |

다른 스킬은 사용 가능한 스킬 목록에 있을 때만 연계한다. 없으면 자체 형식으로 쓴다.

1. 시각 결정
   • 있으면: Skill 도구로 `capture-compare`를 호출해 비교 시트를 만들고 그 경로를 적는다.
   • 없으면: 같은 조건(창 크기·데이터·상태)에서 후보를 직접 캡처해 경로를 나열한다.
     캡처할 수 없는 환경이면 후보별 차이를 표로 쓰고, 실제 화면에서 볼 위치를 적는다.
2. 구조·흐름
   • 있으면: Skill 도구로 `archify`를 호출해 다이어그램 파일을 만들고 그 경로를 적는다.
   • 없으면: 코드 블록 안에 화살표로 흐름을 그린다. 노드가 10개를 넘으면 그리지 않고
     번호 목록으로 단계를 쓴다.
