# 시연 영상 만들기 원칙 (사용자 피드백에서 나옴)

2026-11-24 한 PoC의 공모전 데모 영상을 네 번 고쳐 가며 사용자가 짚은 것들이다. 시나리오를 쓰거나 결과를 보여 주기 전에 이 목록으로 스스로 점검한다. 각 항목의 "왜"를 이해하면 다른 영상에도 맞게 적용할 수 있다.

## 1. 보는 사람이 읽을 시간을 준다

- 자막은 최소 2.8초, 글자 수 × 110ms + 1초가 기본(`hold` 생략 시 자동). 직접 `hold`를 줄 때도 이보다 짧게 잡지 않는다
- 편집기는 출력 영상에서 2초보다 짧게 보이는 자막과 5분을 넘는 길이를 `경고:`로 알린다. **경고가 있으면 사용자에게 보여 주기 전에 고친다**
- 스크롤은 300~500 CSS px/초. 표나 중요한 단락 앞에서는 `hold`를 5~6초로 늘린다
- 한 영상은 5분 안 (사용자 기준). 넘으면 기다림을 `cut`하거나 덜 중요한 단계를 뺀다

왜: 첫 판은 자막 기본이 1.5초였고, 카드 순서 버그로 0.1초 깜빡이는 자막이 있었다. 사용자는 "너무 여유 없이 빠르게 지나간다"고 했다. 발표 때 소리 없이 트는 영상이라 자막이 유일한 설명이다.

## 2. 강조 상자와 번호는 가리키는 것을 가리지 않는다

- 번호 원은 상자 왼쪽 위 **바깥**에, 페이지 배율에 맞춘 크기로 그린다(편집기가 처리). 상자 안 내용·버튼을 덮지 않는다
- 자막에 ①②가 있으면 같은 단계의 상자에 같은 번호를 단다(`validate`가 검사)
- 상자는 화면이 멈춘 구간(hold)에서만 보인다. 미리보기의 `⚠ 상자 위치 바뀜/가려짐`은 align을 키우거나 고정 머리줄을 피하도록 고친다

왜: 100% 배율에서 번호 원이 UI 버튼·글자를 가린다는 지적을 받았다.

## 3. 장면 순서는 영상이 설명하는 "흐름"과 같은 방향으로

- 영상에 흐름도(브릿지 카드의 흐름 띠)를 쓰면, 장면 순서를 **그 흐름의 순서**로 짠다. 강조가 앞으로만 나아가야 보는 사람이 따라온다
- 화면을 여는 순서(사용자 관점)와 처리 순서(시스템 관점)가 다르면 어느 쪽을 축으로 할지 먼저 정하고, 흐름 띠는 그 축과 같은 것을 보여 준다
- 처리 결과가 한 화면에 순서대로 적혀 있으면(예: 상세 페이지의 제목 순서) 그 화면을 위에서 아래로 내려가며 단계 번호를 자막에 붙인다("2 정보 정리", "3·4 근거…")
- 결과물(담당자가 받는 것)은 마지막 장면에 둔다. 흐름의 끝이자 이야기의 마무리다
- 흐름 밖의 것(운영 도구, 설정)은 맨 뒤 별도 장면으로, 흐름 띠는 "모두 지나옴" 상태로

왜: 첫 구성(노트 → 상세 → 콘솔)은 흐름 띠의 불이 끝 → 가운데 → 처음으로 뒤죽박죽 움직였고, 사용자가 "영상의 흐름대로 하나씩 따라가야 한다"고 지적했다.

## 4. 장면 사이에는 다리를 놓는다

- 장면이 바뀌는 단계에 `bridge` 카드(흐린 이전 화면 + 장면 번호·제목·한 줄 설명 + 흐름 띠). 3초
- 맨 앞 `intro`(전체 흐름이 다 켜진 띠), 맨 뒤 `outro`(정리 한 줄)
- 흐름 띠: 지나온 단계 옅은 주황, 지금 진한 주황, 남은 단계 회색(자동). 오래 기다리는 단계에는 `sweep`으로 단계가 차례로 켜지게
- 카드가 이어지면 깜빡임 없이 바로 바뀌고, 카드 끝은 다음 화면으로 녹아든다(편집기 처리)

왜: PoC 시연에서 화면이 갑자기 바뀌면 "지금 무엇을 보는지"를 놓친다. 사용자가 "브릿지 씬이 없어서 확 넘어간 느낌"이라고 했다.

## 5. 숫자로 말할 수 있는 것은 숫자로

- 기다림이 있는 흐름이면 걸린 시간을 자막에: `${since:<시작 단계 id>}` ("약 1분 5초", 녹화 중 측정). 편집으로 줄였다면 "(영상은 기다림을 줄임)"을 붙인다
- 측정값은 지어내지 않는다. `--from`으로 일부만 다시 찍을 때는 이전 녹화에서 잰 값을 `--var "since:p7=…"`로 넘기고 그 사실을 보고에 적는다

## 6. 화면에서 덜어 낼 것

- 탭을 바꾸는 동안 이전 탭이 새 단계 자막과 함께 남지 않게(녹화기·편집기가 처리). 미리보기와 `transitions` 시트에서 확인
- 장면 순서를 바꾸느라 링크를 따라갈 수 없으면 `capture.fetch`(같은 사이트 API)로 주소를 읽어 바로 연다. 화면에 없는 탭 전환을 만들지 않는다
- 필터·검색처럼 서로 조건을 유지하는 UI는 순서를 시험 실행으로 확인한다(검색 뒤 필터 → 빈 목록이었음)

## 7. 보여 주는 방식

- 녹화 전에 시험 실행 + 미리보기 시트로 자막·상자·가리기를 확인받는다
- 시각적인 선택(배율, 카드 모양)은 말로 묻지 말고 같은 화면에서 후보를 찍어 비교 시트로 보여 준다
- 결과 보고는 짧게 번호로: 영상 경로, 길이, 바뀐 점, 가리기 확인 결과, 남은 질문
- 되돌릴 수 없는 단계(실제 데이터 생성)가 있는 녹화는 매번 사용자 확인을 받는다. 자동 안전 검사에 막히면 무엇을 왜 하려 했는지 설명하고, 사용자가 대상·범위를 짚어 다시 허락하면 진행한다
