# docs 페이지 작성법

정식 공개 분류(`engineering/`, `productivity/`)의 스킬마다 `docs/<분류>/<스킬명>.md`를 하나씩 둔다. `SKILL.md`는 에이전트가 읽는 문서이고, docs 페이지는 **스킬을 쓸지 고민하는 사람**이 읽는 문서다. `SKILL.md`의 절차를 다시 옮겨 적지 않는다.

`misc/`, `in-progress/`, `deprecated/`의 스킬에는 docs 페이지를 만들지 않는다. 정식 공개 스킬을 삭제할 때는 페이지를 지우지 않고 맨 위에 보관 표시를 한다: `> 보관됨: 이 스킬은 YYYY-MM-DD에 삭제되었습니다. <대체 스킬 또는 이유>`

## 템플릿

아래 네 섹션을 이 순서로 쓴다. 섹션 사이에 그 스킬에 필요한 섹션을 더 넣어도 된다(예: 흔한 실수, 다른 스킬과의 관계).

```markdown
## 무엇을 하나

<스킬이 하는 일. 입력과 결과물, 남기는 파일이 있으면 무엇인지.>

## 언제 쓰나

<쓰기 좋은 상황과 쓰지 말아야 할 상황. user-invoked인지 model-invoked인지. 비슷한 스킬과 어떻게 고르는지.>

## 자주 묻는 질문

**<질문>**
<답>

## 잘 되고 있다는 신호

- <제대로 쓰고 있을 때 관찰되는 것>
```

## 질문은 어디서 찾나

"자주 묻는 질문"은 지어내지 않는다. 다음에서 찾는다.

- 이 저장소의 이슈와 Discussions
- 스킬을 쓰다가 직접 헷갈렸던 지점, 에이전트가 잘못 따라 했던 지점
- `SKILL.md`에서 "하지 않는다"로 막아 둔 규칙: 막아 둔 이유가 곧 질문이 된다

## 다시 맞출 때

스킬의 동작을 바꾸면 docs 페이지도 같은 변경에서 고친다. 페이지에 적힌 동작이 `SKILL.md`와 다르면 `SKILL.md`가 맞다.
