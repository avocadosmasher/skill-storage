# 스킬 설계 기록은 `.agents/design/<스킬>/`에 공개로 둔다

- 날짜: 2026-10-14
- 상태: 채택

## 배경

`gated-tdd`를 승인 피로 문제로 개편하면서, 스킬을 깎아 나가는 과정(설계 의도, 검토한 선택지, 고른 안, 방향이 바뀐 이유)을 남기기로 했다. 다음에 스킬을 고치는 에이전트가 바로 읽고 "전에 이렇게 하려고 했구나"를 알 수 있어야 한다.

처음 요청은 "설치하는 사람에게는 내려가지 않고 저장소 주인만 소유"였다. 이 저장소는 공개이고 플러그인은 `source: "./"`로 저장소 전체를 사용자 캐시에 복사하므로, 저장소에 커밋한 파일을 주인만 읽게 하는 방법은 암호화뿐이다.

## 검토한 선택지

| 안 | 주인만 읽기 | 추가 관리 | 클라우드 세션·Codex에서 읽기 |
| --- | --- | --- | --- |
| A. 공개 `.agents/design/` | 안 됨 | 없음 | 됨 |
| B. 암호화(git-crypt, SOPS) | 됨. 파일 이름과 커밋 메시지는 공개 | 기기마다 잠금 해제, 키 백업. GitHub 웹에서 주인도 못 읽음 | 키를 넘겨야 해서 사실상 안 됨 |
| C. 서브모듈 | 됨 | 기록할 때마다 두 번 커밋 | clone 설정 필요 |
| D. 비공개 저장소를 `.agents/private/`에 clone하고 gitignore | 됨 | push가 두 군데 | AGENTS.md 지시 한 줄로 됨 |
| E. 비공개 원본 + 공개 미러 | 됨 | 동기화 자동화, 외부 PR 이식 | 됨 |

## 결정

A로 시작한다. 관리 부담이 없고, 어떤 에이전트든 저장소만 받으면 바로 읽는다. 오픈소스 프로젝트는 설계 결정을 대개 공개하며, 이 저장소의 ADR도 이미 공개다.

- `.agents/design/`은 플러그인 사용자의 컨텍스트에 들어가지 않고(스킬만 로드됨), skills.sh 설치에도 복사되지 않는다. 플러그인 캐시에는 저장소 전체가 복사되므로 파일은 들어 있다.
- 형식과 읽는 법은 [.agents/design/README.md](../design/README.md)에 있다.

## 비공개로 바꿀 때

기록에 공개하기 어려운 내용(개인 프로젝트 정보, 미공개 계획)이 들어가기 시작하면 바꾼다.

- **D가 1순위다.** 빈 비공개 저장소(예: `skill-storage-notes`)를 만들고, `.agents/design/`의 내용을 옮긴 뒤 `.agents/private/`에 clone하고 `.gitignore`에 추가한다. AGENTS.md의 "스킬 설계 기록" 절을 "`.agents/private/`가 있으면 읽고, 비어 있고 접근 권한이 있으면 clone한다"로 바꾼다. 이미 공개로 커밋한 기록은 git 이력에 남으므로, 지워야 한다면 이력 재작성이 필요하다.
- **B**는 저장소를 하나로 유지해야 하는 이유가 생겼을 때만 고려한다. 클라우드 세션에서 읽을 수 없다는 점이 가장 큰 비용이다.

## 결과

- 스킬을 고치는 에이전트는 AGENTS.md 지시에 따라 고치기 전에 `.agents/design/<스킬>/README.md`를 읽는다.
- 설계 결정이 GitHub에서 공개된다.
