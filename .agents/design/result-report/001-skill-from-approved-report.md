# 001. 승인된 프로젝트 보고서 형태를 범용 스킬과 틀로 뽑아 productivity에 정식 공개

- 날짜: 2026-11-15
- 상태: 채택
- 반영: 1.13.0

## 배경

한 사이드 프로젝트에서 주차 결과 보고서를 HTML로 만들며 형태를 여러 번 고쳤다.

- "가시성 좋은 보고서" 요청에 화려한 화면을 만들었다가 "그냥 깔끔한 보고서"로 다시 만들었다.
- 너무 함축돼 와닿지 않는다는 말에, 무엇을 만들었고 어떤 역할인지 풀어 쓴 절을 더했다.
- 사용자는 제품 방향과 결과에 책임을 지고 코드는 에이전트가 쓰는 상황이라, 함수 이름 위주 설명이 이해되지 않는다는 지적이 있었다. 기능은 쉬운 말로, 함수는 "구현" 칩으로 붙이게 바꿨다.
- 전체 흐름 그림에 이번 작업 · 동료 · 함께 · 이미 한 것 · 아직 안 한 것을 색으로 나누고, 칩도 코드 종류별 색으로 나눠 한 줄씩 나열했다.
- 문장 끝을 명사형 어미로 맞췄다.

사용자가 이 형태를 승인하고 "다른 프로젝트에서도 이런 보고서를 쓰고 싶다"고 했다.

## 선택지

- **A. 이 저장소에 스킬로 추가**: 틀과 작성 규칙이 함께 다니고, 플러그인으로 어느 프로젝트에서나 쓴다. 처음에 스킬 문서를 써야 한다.
- **B. 틀 파일만 공용 폴더에 둠**: 바로 되지만, 작성 규칙(구조 · 문체 · 색 · 칩)은 원래 프로젝트의 기억에만 있어 다른 프로젝트에서 빠진다.
- **C. 노션 템플릿**: 공유는 쉽지만 색 칸 그림 · 칩 · 모바일 배치를 재현하지 못한다.

분류는 `in-progress/`(베타, 플러그인에 넣지 않음)와 `productivity/`(정식 공개, 플러그인에 포함)를 놓고 봤다.

## 결정

A, `productivity/`. 목적이 다른 프로젝트에서 바로 쓰는 것이라 플러그인에 들어가야 한다. 형태는 이미 한 프로젝트에서 여러 번 고쳐 승인된 것이다.

원래 프로젝트 전용이던 두 곳을 일반화했다.

- 칩 종류: CLI 명령 · 에이전트 정의 · 실행 함수 · 도구 · 함수를 진입점 · 정의 · 흐름 · 도구 · 함수로 바꾸고, 클래스 이름도 `c-entry` · `c-config` · `c-flow` · `c-tool` · `c-fn`으로 바꿨다. 프로젝트별 예를 `SKILL.md` 표에 둔다.
- 그림 색: 특정 동료 이름이 박힌 클래스를 `b-peer`로 바꾸고 범례를 "나 · 동료"로 쓴다.

원래 프로젝트의 실제 보고서는 비공개 내용이 있어 예시로 넣지 않았다.

## 버린 것과 미룬 것

- B · C는 위 이유로 버렸다.
- 마크다운 · 노션으로 내보내기는 필요가 생기면 본다.
- 실제 보고서 예시(가상의 프로젝트로 채운 것)를 `references/`에 두는 일은 미뤘다.

## 다시 볼 신호

- 다른 프로젝트에서 쓸 때 칩 다섯 종류나 그림 층 구성이 자주 맞지 않는다.
- 사용자가 보고서를 고친 내용이 이 틀과 반대 방향이다.
- 에이전트가 틀의 `{{ }}`를 남기거나, 기록에 없는 수치를 채운다.
