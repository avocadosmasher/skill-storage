# result-report 설계 기록

## 의도

끝낸 작업을 코드를 열지 않는 사람도 읽을 수 있는 HTML 결과 보고서 한 장으로 정리한다. 저장소 주인이 한 사이드 프로젝트의 주차 보고서를 여러 번 고쳐 다듬은 형태를 틀로 뽑아, 다른 프로젝트에서도 같은 형태로 쓰게 한다([001](./001-skill-from-approved-report.md)).

## 현재 원칙

1. 한 열 문서체. 화려한 카드 · 대시보드를 쓰지 않는다([001](./001-skill-from-approved-report.md)).
2. 맥락 먼저, 핵심 로직 중심, 쉬운 말. 함수 이름은 설명의 주어가 아니라 "구현" 칩으로 첨부한다([001](./001-skill-from-approved-report.md)).
3. 흐름 그림의 칸 색은 누가 언제 만든 것인지(이번 작업 · 동료 · 함께 · 이미 한 것 · 아직 안 한 것), 구현 칩의 색은 코드 종류다. 종류 이름은 프로젝트에 맞게 바꿔 쓴다([001](./001-skill-from-approved-report.md)).
4. 문장 끝은 명사형 어미가 기본이고, 사용자가 정한 문체가 우선한다.
5. 기록에 없는 수치 · 이유를 지어내지 않는다.
