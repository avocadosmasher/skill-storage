# 002. 어느 모델이 써도 같은 모양이 나오게 디자인 명세 · 완성 예시 · 검사 스크립트를 둔다

- 날짜: 2026-11-15
- 상태: 채택
- 반영: 1.13.0

## 배경

001로 틀과 작성 규칙을 스킬로 만든 뒤, 사용자가 "디자인은 지정 안 하냐, 어떤 모델에게 물어봐도 유사한 결과물을 받았으면 해서 세세하게 했으면 한다"고 했다. 틀 하나와 글로 된 원칙만으로는 모델마다 CSS를 고치거나, 새 클래스를 만들거나, 칸에 글을 길게 넣거나, 칩을 두 열로 놓는 등 결과가 달라질 여지가 있었다.

## 선택지

- **A. SKILL.md에 규칙을 더 적기만**: 간단하지만, 규칙을 지켰는지 확인할 방법이 모델의 자기 점검뿐이다.
- **B. 디자인 명세 + 완성 예시**: 쓸 수 있는 부품 · 글 길이 · 색의 뜻을 표로 고정하고, 가상 프로젝트로 채운 예시를 기준으로 준다. 모델이 따라 할 구체적인 모양이 생긴다.
- **C. B + 검사 스크립트**: 기계로 확인할 수 있는 규칙(CSS 그대로, 남은 자리, 정해진 클래스만, 절 구성, 칩 한 줄 하나 · 종류 순서, 범례와 실제 사용 일치, 금지 요소)을 스크립트가 실패로 막고, 글 길이 · 문체는 경고로 알린다.

## 결정

C. 모델이 달라도 같은 틀 · 같은 예시를 보고, 같은 검사를 통과해야 끝나게 했다.

- `references/design.md`: 고정하는 것, 디자인 값, 부품마다 HTML 모양과 글 길이, 글 규칙, 모바일, 검사.
- `references/example.html`: 가상의 독서 기록 웹앱 2주차 보고서. 다섯 색 그림, 칩 다섯 종류, 결정 표, 남은 과제까지 모든 부품을 쓴다. 실제 프로젝트 내용은 넣지 않는다.
- `scripts/check-report.mjs`: Node 표준 라이브러리만 쓴다. 실패가 있으면 종료 코드 1.
- 틀의 CSS에서 쓰지 않던 옛 클래스(`.flow`, `.tag`, `.legend`)를 지우고 모바일 규칙을 맨 끝으로 옮겼다. CSS 맨 위에 "디자인 v1, 고치지 않는다" 주석을 넣었다.
- 글 길이 기준(칸 이름 14자, 칸 설명 35자, 칩 설명 30자, 요약 핵심 80자)은 승인된 원래 보고서가 대부분 들어오는 값으로 정했다. 넘으면 실패가 아니라 경고다.

## 버린 것과 미룬 것

- A는 확인 수단이 없어 버렸다.
- 문장 끝 명사형 검사는 경고로만 둔다. 사용자가 다른 문체를 정할 수 있고, 표 항목처럼 문장이 아닌 글을 정확히 가르기 어렵다.
- 브라우저 캡처를 스크립트로 자동화하는 일은 미뤘다. 브라우저 설치가 환경마다 달라, 지금은 SKILL.md 절차로 캡처한다.

## 다시 볼 신호

- 검사를 통과했는데도 모델마다 모양이 눈에 띄게 다르다(검사에 빠진 규칙이 있다).
- 정상적인 보고서가 경고를 자주 받는다(글 길이 기준이 빡빡하다).
- 사용자가 틀 밖의 모양(새 부품)을 반복해서 원한다. 그때는 명세 · 틀 · 예시 · 검사에 부품을 함께 더한다.
