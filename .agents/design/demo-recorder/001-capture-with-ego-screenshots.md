# 001. 녹화는 ego lite 조작 + 스크린샷 반복

- 날짜: 2026-11-24
- 상태: 채택
- 반영: 첫 추가

## 배경
사용자가 원한 기능: 브라우저만 캡처, 브라우저 조작, 오래 걸리는 작업은 배속이나 자르기, 자막, 강조 상자, 순서 번호. 로그인된 사내 서비스(Jira, Confluence, 로컬 콘솔)를 그대로 찍어야 했다.

## 선택지
- 기존 스킬(2026-11-24 `npx skills find` 조사): 요청을 가짜로 바꿔 찍기(로그인 앱에 맞지 않음), 특정 에이전트 브라우저 전용, 새 브라우저를 띄우는 것, 모바일·가짜 터미널 전용. 로그인된 실제 브라우저를 조작하며 녹화하는 것은 없었다
- 화면 녹화 프로그램(OS 수준): 창 전체가 찍히고 다른 창·알림이 섞임
- `Page.startScreencast`: 프레임이 오지만 ego가 ack(`sessionId`)를 막아 3장 뒤 끊김
- `Page.captureScreenshot` 반복: 조작과 동시에 초당 13~27장, 페이지 내용만

## 결정
ego lite를 조작하는 같은 스크립트 안에서 `Page.captureScreenshot`을 await 없는 루프로 반복한다. 화면 크기는 `Emulation.setDeviceMetricsOverride`로 고정해(창이 작아도) 프레임이 정확히 1920×1080이 되게 한다. 편집기가 가변 간격 프레임을 30fps로 다시 맞춘다.

## 버린 것과 미룬 것
- screencast: ego가 ack를 허용하면 다시 볼 만하다(더 부드러움)
- 커서: 캡처에 실제 커서가 없어 편집에서 그린다

## 다시 볼 신호
- ego 창이 가려지면 Chrome이 그리지 않아 캡처가 멈춘다. 시작 전 시험 캡처와 3초 연속 실패 중단으로 막았지만, 자주 걸리면 화면 밖 렌더링 방법을 찾는다
