# 002. 소제목의 탐색성과 글의 범위, 사용자 교정 반영 기준

- 날짜: 2026-10-29
- 상태: 채택
- 반영: skill-storage 1.11.1

재사용할 교정의 편입 위치는 후속 [004](./004-incorporate-feedback-into-skill.md)에서 보완했다. 아래의 소제목·범위·교정 비교 기준은 유지한다.

## 배경

skill-storage 소개 글의 실제 리뷰에서 사용자는 소제목만 보고 아래 내용을 예측하고 필요한 정보를 찾을 수 있어야 한다고 설명했다. AI 초안은 질문 중심 문체를 소제목의 호기심 유발로 확대했고, 저장소를 소개하는 글에 개별 스킬 사용법을 길게 넣었다. 사용자는 변동이 잦은 현행 스킬 소개를 삭제하고 저장소의 구조·운영에 집중했다. 사용자 수정본에는 설명 보강과 말투 교정도 있어 실제 비교가 필요했다.

## 선택지

- 모든 소제목의 의문형 금지: 단순하지만 구체적인 FAQ·문제 진단 제목까지 제한
- 이 블로그의 선호만 저장: 당장은 도움이 되지만 공용 스킬의 구성 판단 빈틈이 남음
- 공용 스킬에는 탐색·범위·교정 비교 기준을, 블로그에는 저자별 선호를 기록: 재사용 범위가 분명해 이 안을 채택

## 결정

- 소제목은 대상과 내용 범위를 드러내고 본문과 일치. 질문 중심 설명을 제목 형식으로 강제하지 않음
- 사례는 글의 목적과 정보의 수명을 보고 선택. 모든 기능 목록·스킬 이름·사례를 금지하지 않음
- 최신 사용자 원문을 보존해 이전 초안과 비교하고, 명시적 교정·추정·오탈자·새 기술 주장을 구분
- 상세 기준은 composition.md 한곳에 두고 SKILL·voice·설명 페이지에서 연결
- 기존 001의 출처·저자 교정 우선 원칙은 유지. 이 결정은 편집 기준 보완

## 버린 것과 미룬 것

- 제목의 정보성과 글의 적합성을 문자열 린트만으로 증명하는 장치, 모든 글에 고정 목차·고정 사례 수를 요구하는 규칙은 추가하지 않음
- 특정 저자의 농담·문장 끝을 공용 스킬에 강제하지 않음

## 다시 볼 신호

- 내용을 예고하는 제목이 지나치게 길어지거나, 필요한 사례까지 빠져 이해가 어려워지는 리뷰
- 사용자 교정을 한 번의 오탈자나 문단 나누기까지 절대 규칙으로 확대하는 사례
