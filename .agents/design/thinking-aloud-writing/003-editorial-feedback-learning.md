# 003. 수정 이유를 분석하고 저자 선호를 다음 집필에 반영

- 날짜: 2026-11-02
- 상태: 대체됨 (004)
- 반영: feat/writing-feedback-learning, 미배포

후속 사용자 교정으로 [004](./004-incorporate-feedback-into-skill.md)가 외부 선호 기록을 기본으로 삼는 배치 결정을 대체했다. 아래 내용은 당시 판단의 기록이며 현재 편입 절차는 004와 스킬 본문을 따른다.

## 배경

블로그 도입 리뷰에서 사용자는 문장 끝이나 접속어보다 주제에 들어오기 전의 배경과 개인의 생각이 빠진 점을 지적했다. 이어서 글쓰기에는 스타일·선호 차이가 있으므로 수정 요청을 분석해 스킬을 지속적으로 개선하고 싶다고 요청했다. 기존 002에는 수정본 비교와 개인 취향의 범위 구분이 있지만, 기록을 어디에 남기고 다음 집필에서 어떻게 다시 읽을지는 충분하지 않았다.

## 선택지

- 교정할 때마다 공용 스킬에 문체 규칙 추가: 즉시 반영되지만 특정 저자의 취향이 모든 사용자에게 적용되고 상충하는 규칙이 쌓임
- 현재 원고만 수정: 가볍지만 새 글·새 세션에서 같은 설명을 반복해야 함
- 수정 이유를 분석하고 저자 기준과 공용 절차를 나누어 관리: 기록 경로 연결이 필요하지만 지속적인 개인화와 공유 스킬의 재사용성을 함께 유지할 수 있어 채택

## 결정

- 수정 요청·불만·대체 문장이 오면 현재 원고를 고치면서 문제의 단위와 이유를 분석한다. 사용자가 밝힌 이유를 우선하고 추정은 표시한다.
- 사실 교정, 이번 글의 선택, 지속적인 저자 선호, 공용 절차의 누락을 구분한다. 기록된 선호를 다음 집필 시작과 전달 전 검토에서 사용한다.
- 기존 프로젝트 작성 기준을 우선한다. 임시 메모만 가능한 경우 인계에 연결하고 프로젝트 전체 적용으로 과장하지 않는다. 다른 도구의 상태 파일을 새로 소유하지 않는다.
- 지속 개선 요청은 요청 범위 안에서 이어갈 수 있으나 커밋·푸시·배포나 개인 자료 공개의 승인은 아니다. 설치 캐시를 수정하지 않고 원본 저장소에서 검증한다.
- 001의 현재 지시 우선, 002의 개인 선호와 공용 판단 기준 구분을 유지하며 구체적인 피드백 절차로 보완한다. 자세한 절차는 editorial-feedback.md에 두고 진입점과 기존 참고 자료에서 연결한다.

## 버린 것과 미룬 것

- 모든 글에 동일한 도입 순서·인사말·문단 수를 강제하지 않는다.
- 매 수정마다 별도 승인·긴 분석 보고서를 만들지 않는다. 개인화를 모델 재학습이나 모든 AI의 자동 준수로 표현하지 않는다.
- 선호를 자동으로 추출·강제하는 별도 프로그램, 원격 동기화, 스킬 배포 자동화는 이번 변경에 포함하지 않는다.

## 다시 볼 신호

- 다른 글에서 같은 선호를 반복해서 설명해야 하거나 새 세션이 기준 파일을 찾지 못하는 사례
- 일회성 수정·작업 대화 문체가 지속 선호가 되거나, 다른 저자의 기준에 섞이는 사례
- 추정한 취향이 확정 규칙처럼 적용되거나 이전 기준과 충돌하는 지시가 누적되는 사례
