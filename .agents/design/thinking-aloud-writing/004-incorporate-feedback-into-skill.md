# 004. 사용자 교정을 스킬의 활성 작성 기준에 편입

- 날짜: 2026-11-03
- 상태: 채택
- 반영: feat/writing-feedback-learning, 미배포

## 배경

사용자는 수정 요청을 분석해 스킬을 지속적으로 개선하고 싶다고 요청했다. 003은 개인 취향을 프로젝트의 별도 기준에 저장하고 다음 세션이 찾아 읽도록 해석했으나, 사용자는 단순 기록을 넘어 스킬로 편입하는 것이 목적이라고 바로잡았다. 또한 스킬을 사용하는 현재 사용자가 저자이므로 여러 저자를 식별·관리할 필요가 없다고 명시했다.

Claude Code와 Antigravity의 평가 및 후속 재검토는 외부 메모 발견 경로의 보완점을 제시했지만, 그것만 보완하면 처음 의도를 충족하지 못한다. 평가에서 다룬 문제를 해결하기에 앞서 개선의 최종 산출물을 바로잡는다.

## 선택지

- 외부 기준의 저장·조회 경로만 보완: 기존 구현 변경은 작지만 사용자가 원하는 스킬 편입이 아님
- 교정 내용을 무조건 SKILL.md에 추가: 일회성 수정·사실·추정까지 규칙으로 쌓이고 진입점이 비대해짐
- 교정의 재사용 범위를 분석해 기존 스킬 참고 문서와 절차에 편입: 기존 문체·구성 기준을 실제로 개선하고 일반 집필 경로에서 다시 읽을 수 있어 채택

## 결정

- 현재 세션의 사용자를 저자로 간주한다. 저자 등록·선택·다중 저자 분리 절차는 추가하지 않는다.
- 지속 개선을 요청받은 범위에서 원고와 스킬을 함께 고친다. 말투·도입은 voice.md, 구성·설명은 composition.md, 작업 판단은 SKILL.md나 editorial-feedback.md의 해당 항목을 갱신한다.
- 날짜·오탈자·이번 글의 선택은 원고와 작업 기록에서 처리한다. 추정한 취향은 확정된 스킬 규칙으로 만들지 않는다. 명시적인 앞으로도 요청은 한 번이어도 편입할 수 있다.
- 사용자 문장의 표면을 복사하지 않고 해결한 문제와 적용 조건을 작성 기준으로 만든다. 이번에 확인한 도입 흐름도 voice.md에 실제 반영한다.
- 외부 기록은 변경 이유·근거를 남기는 용도이며 활성 작성 기준을 대신하지 않는다. 일반 집필은 스킬 안의 기준을 읽으므로 선호 파일의 프로젝트별 탐색을 기본 경로로 요구하지 않는다.
- 공유하는 초기 프로필은 사용자가 선택할 출발점이며 각 사용자는 자기 사본을 개선할 수 있다. 설치 캐시는 고치지 않는다. 원본을 고칠 수 없으면 변경안·수정 가능한 사본을 준비하고 미반영 범위를 알린다.
- 원고만 맡긴 작업에서 공유 원본 수정까지 허가받았다고 확대하지 않는다. 요청받은 지속 개선은 같은 허락을 반복해 묻지 않되 커밋·푸시·배포는 저장소 절차를 따른다.
- 003의 원문 비교·수정 이유 분석·검증 한계와 002의 제목·범위 판단은 유지한다. 개인 교정의 최종 편입 위치를 외부 기준으로 고정한 결정은 대체한다.

## 버린 것과 미룬 것

- 별도 저자 레지스트리·선호 상태 파일·자동 추출 엔진은 만들지 않는다.
- 모든 교정을 공용 기본값으로 강제하거나 여러 설치자의 사본을 자동 갱신하지 않는다.
- 모든 AI의 규칙 준수나 새 세션 재현을 문서 변경만으로 입증했다고 말하지 않는다. 실제 실행한 검사와 평가만 보고한다.

## 다시 볼 신호

- 외부 메모만 바뀌고 스킬의 활성 기준은 바뀌지 않은 사례
- 일회성 요청·추정이 문체 규칙으로 쌓이거나 활성 규칙끼리 충돌하는 사례
- 같은 스킬 버전으로 새 글을 쓰는데 이미 반영한 교정을 다시 설명해야 하는 사례
