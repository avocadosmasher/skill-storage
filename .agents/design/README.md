# 스킬 설계 기록

스킬이 **왜 지금 모양이 되었는지**를 남기는 곳이다. 어떤 선택지를 놓고 무엇을 골랐는지, 방향이 왜 바뀌었는지를 적어 둔다. 스킬을 고치는 에이전트가 바꾸기 전에 읽고, 이미 버린 길로 되돌아가거나 의도와 어긋난 변경을 하지 않게 하는 것이 목적이다.

`.agents/adr/`과의 구분:

| 위치 | 담는 것 |
| --- | --- |
| `.agents/adr/` | 저장소 전체 구조에 관한 결정 (분류 폴더, 플러그인 구성, 기록 위치 등) |
| `.agents/design/<스킬>/` | 스킬 하나의 동작 설계 (절차, 규칙, 스크립트가 왜 그렇게 동작하는지) |

이 폴더는 공개 저장소에 있으므로 누구나 GitHub에서 읽을 수 있다. 플러그인 사용자의 컨텍스트에는 들어가지 않고, skills.sh 설치에도 복사되지 않는다. 비공개로 바꿀 때의 선택지는 [ADR 0003](../adr/0003-skill-design-records.md)에 있다.

## 구조

```
.agents/design/<스킬>/
  README.md        의도와 현재 원칙, 결정 목록 (먼저 읽는 파일)
  NNN-<주제>.md    결정 하나당 파일 하나
```

## 읽을 때

1. 스킬을 고치기 전에 `<스킬>/README.md`를 읽는다. 의도와 현재 원칙, 결정 목록 표가 있다.
2. 바꾸려는 부분과 관련된 결정 파일만 연다. 전부 통독하지 않는다.
3. 바꾸려는 내용이 현재 원칙이나 채택된 결정과 부딪히면, 고치기 전에 사용자에게 그 결정과 충돌한다는 사실을 알린다.

## 쓸 때

- 선택지가 있었던 결정, 방향을 바꾼 결정, 사용자의 제안을 고쳐서 받아들인 결정을 남긴다. 오타 수정이나 문구 정리는 남기지 않는다.
- 결정한 그 대화에서 바로 쓴다. 나중에 복원하려 하면 이유가 사라진다.
- 기존 결정을 뒤집으면 기존 파일은 지우지 않고 상태를 `대체됨 (NNN)`으로 바꾸고, 새 파일에 왜 바뀌었는지 쓴다.
- `<스킬>/README.md`의 결정 목록 표와 현재 원칙도 같은 변경에서 고친다.

결정 파일 형식:

```markdown
# NNN. <결정 한 줄>

- 날짜: YYYY-MM-DD
- 상태: 채택 | 보류 | 대체됨 (NNN)
- 반영: <버전 또는 커밋>

## 배경
<어떤 문제나 요청에서 시작했는지. 사용자가 낸 원래 제안이 있으면 그대로 요약한다.>

## 선택지
<검토한 안마다 장점과 단점.>

## 결정
<고른 안과 이유.>

## 버린 것과 미룬 것
<고르지 않은 안, 나중으로 미룬 것.>

## 다시 볼 신호
<이 결정을 바꿔야 할 수도 있다는 관찰 신호.>
```
