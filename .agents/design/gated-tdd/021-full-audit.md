# 021. 스킬 전체 점검: 버그는 바로 고치고, 방향이 필요한 것은 하나씩 정한다

- 날짜: 2026-10-26
- 상태: 진행 중 (묶음 A 반영, 묶음 B 논의 중, 묶음 C 보류)
- 반영: 묶음 A는 skill-storage 1.8.1, gated-tdd-budget 0.1.1

## 배경

작은 수정 경로([020](./020-small-fix-path.md))를 마친 뒤 사용자가 스킬 전체 점검을 요청했다. 새 컨텍스트 에이전트 셋이 나눠 봤다.

1. 여러 상황에서 문제가 생길 여지. 임시 저장소에서 훅을 실제로 돌려 재현했다.
2. 지시문 사이의 충돌.
3. 다른 스킬·도구와 함께 쓸 때 파일 위치와 이름이 겹치는지.

약 40건이 나왔고, 겹치는 것을 합쳐 세 묶음으로 나눴다.

## 묶음 A: 정할 것 없이 고친 버그 (반영)

- 한글 경로: 훅이 git 출력의 경로를 8진수로 바뀐 이름으로 읽었다. 기존 한글 테스트를 고쳐도 검사에 걸리지 않았고, 한글 이름 테스트를 새로 추가하면 판정 뒤에도 커밋이 막혔다. `-z` 출력으로 읽는다. 이 PC는 전역 `core.quotePath=false`라 드러나지 않았다.
- 이름 변경: 새 경로만 봐서, 테스트나 마이그레이션을 패턴 밖으로 옮기면 판정 없이 통과했다. 옛 경로도 본다.
- 바이너리 스냅숏: 줄 단위 diff가 없어 기대값 이미지 변경이 빠졌다. 테스트 경로의 바이너리 변경을 보호 대상으로 보고, 기본 `tests`에 `**/__snapshots__/**`, `**/*-snapshots/**`를 더했다.
- 훅 실행 권한: `git update-index --chmod=+x .githooks/*`는 PowerShell에서 `*`가 펼쳐지지 않아 실패한다. 파일 세 개를 이름으로 적고 `100755`를 확인한다.
- `log-new.mjs`: Prettier가 바꾼 표 구분선을 읽지 못했고, 실패해도 항목 파일만 남았으며, 하위 폴더에서 실패했다. 모두 확인한 뒤 쓰고, 저장소 루트에서 돌며, 원래 줄바꿈을 따른다.
- 예산 단위 수: pull로 받은 남의 커밋까지 세어 거짓 정지가 났다. `post-commit`에서 불린 커밋만 세션 기록에 더해 센다. 선택지는 작성자·시각으로 거르기와 훅에서 기록하기였고, 리베이스나 같은 사람의 다른 PC 커밋에도 맞는 뒤쪽을 골랐다.
- 예산 mod: Bash 도구만 봐서 Windows의 PowerShell 도구 커밋에는 수치가 빠졌다. 둘 다 본다. mod 테스트는 엔진이 경로를 OS 절대 경로로 넘기게 바뀌어 Windows에서 이미 실패하고 있었고, 비교 전에 경로를 맞추게 고쳤다.
- Node 18 이상 전제를 도입 절차와 문서에 적었다.
- 결정·확인 통과 뒤 로그 제목, INDEX 상태 칸, STATUS를 `통과`로 바꾸는 단계가 없어 `판정 대기`가 남았다. 5절에 넣었다.
- 표현 통일: 작은 수정 조건은 셋(④는 조건이 아니라 처리 방법), "수용 기준"·"인수 조건"은 "인수 기준", 훅 오류 문구는 계획 판정 범위 안의 approve도 허용한다고 씀, 자동 진행 내역은 "맨 위"가 아니라 결론 바로 아래.

## 묶음 B: 방향을 정할 것 (논의 중)

- B1. 다른 git 훅 도구(husky 등)와 `core.hooksPath`가 서로 끄는 문제. [019](./019-third-simulation-fixes-and-backlog.md)의 "세션 시작에 훅 경로를 되돌린다"와 충돌한다.
- B2. 브랜치를 동시에 진행하면 `STATUS.md`, `docs/log/INDEX.md`, 로그 번호가 매번 충돌하고 다른 브랜치의 대기 항목이 보이지 않는다. "세션 시작에 STATUS.md만 읽는다"와 [005](./005-unconfirmed-checkpoints-block.md)에 닿는다.
- B3. 기능 브랜치에 main을 병합하면 이미 판정받은 보호 대상 변경을 다시 막는다. 사용자는 "병합해 들어온 쪽과 같은 내용은 빼기"에 동의하되 다른 시각의 검토를 한 번 더 요청했다.
- B4. 대상 저장소의 `scripts/`에 복사하는 파일 이름이 프로젝트 파일, 테스트 도구의 기본 수집 범위와 겹친다.
- B5. superpowers, grill-me-plus처럼 계획·결정 문서를 쓰는 다른 스킬과 문서가 두 벌 생긴다.
- B6. 정식 절차로 올리거나 급한 일이 끼어들 때 커밋하지 않은 작업이 다음 판정을 막는다. 사용자 조건: 미뤄 둔 일이 잊히거나 지워지지 않아야 한다.
- B7. 동작을 보존하는 작업(리팩터링, 의존성)이 요구를 생략하는지 SKILL.md·[012](./012-requirements-for-every-change.md)와 `requirements.md`가 다르게 말한다.

## 묶음 C: 보류 (기록만)

사용자 결정: "일단 기록만 해두고 나중에 진행. 핵심 부분부터 완성하자."

- 병합 뒤 되돌리기(revert) 절차가 없다.
- GitLab, `gh`가 없는 환경, `develop` 브랜치 기반 흐름.
- 판정 대기 상태가 커밋되지 않아 다른 PC나 클라우드 세션에서 보이지 않는다.
- `docs/`가 공개 문서 사이트(MkDocs, GitHub Pages)인 저장소. 문서 위치 옵션이 필요할 수 있다.
- commitlint, release-please 같은 커밋 규칙 도구를 읽지 않는다.
- archify가 저장소에 `.archify/`를 남긴다.
- 이미 다른 용도로 쓰는 `STATUS.md`, `CLAUDE.md` "첫 줄" 요구의 취약함.
- `.git/manual-review.*` 이름에 스킬 접두사가 없다.
- 기본 보호 목록에 잠금 파일(`package-lock.json` 등), 다른 생태계 매니페스트(`composer.json`, `*.csproj`, `pubspec.yaml`, `Package.swift`), `.gitlab-ci.yml`, RSpec `spec/`이 없다.
- 끝에 줄바꿈이 없는 테스트에 줄을 덧붙이거나 CRLF를 LF로 바꾸면 "기존 줄 변경"으로 잘못 막힌다.

## 다시 볼 신호
