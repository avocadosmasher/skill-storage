# 002. 게이트는 세 등급, AI가 제안하고 사용자가 확정, 실행 중에는 올리기만

- 날짜: 2026-10-14
- 상태: 채택
- 반영: skill-storage 1.5.0

## 배경

[001](./001-approval-boundary-by-questions.md)의 판정 질문을 실행 중에 매번 적용하면 AI의 해석이 흔들리고, 애매할 때마다 묻게 된다. 그 해석이 언제, 누구의 승인으로 정해지는지가 필요했다.

## 선택지

1. **실행 중에 AI가 단위마다 판정한다.**
   - 장점: 계획이 가볍다.
   - 단점: 분류 실수를 사용자가 볼 기회가 없다. 애매하면 묻게 되어 피로가 돌아온다.
2. **계획에서 행마다 등급을 정한다. AI가 제안하고 사용자가 확정한다.** (채택)
   - 장점: 결정을 계획 단계로 당겨 한 번에 받는다. 실행 중에는 예외만 멈춘다. 승인 범위가 계획에 적혀 있어 "앞선 승인이 이 행동까지 덮는가"를 따질 때 근거가 된다.
   - 단점: 계획을 세울 때 할 일이 늘어난다.
3. **사용자가 등급을 직접 정한다.**
   - 단점: 사용자가 모든 행을 따져야 해서 피로를 계획 단계로 옮겨 놓을 뿐이다.

## 결정

- 등급은 셋이다. **결정**(판정 질문 ①②③, 즉시 멈춤), **확인**(④, 확인 지점에서 묶어서), **자동**(기록과 알림).
- 계획의 작업 표에 `게이트` 열을 두고 AI가 제안, 사용자가 확정한다.
- **래칫**: 실행 중 AI는 등급을 올릴 수만 있다(자동에서 확인이나 결정으로). 내리려면 사용자 허락이 필요하다. 분류 실수가 "더 묻는" 쪽으로만 나게 한다.

auto mode 분류기가 가장 자주 틀린 지점이 "앞선 승인이 이 행동의 영향까지 덮는가"였다는 Anthropic의 보고(2026-03)도 승인 범위를 계획에 글로 남기는 근거가 되었다.

## 버린 것과 미룬 것

- 등급을 넷 이상으로 나누는 안(예: 결정 중에서도 비용만 따로)은 판정이 복잡해져 버렸다. 필요하면 결정 게이트 보고 안에서 쟁점별로 나눈다.

## 다시 볼 신호

- 계획 단계의 등급 확정 자체가 부담이 된다. (행이 너무 많거나 제안이 부정확함)
- 실행 중 등급을 올리는 일이 잦다. (계획 단계의 제안이 체계적으로 낮음)
