# 019. 세 번째 시뮬레이션의 빈 곳을 고치고, 기능 내용에 관한 판단은 미룬다

- 날짜: 2026-10-20
- 상태: 채택 (일부 보류)
- 반영: skill-storage 1.7.0

## 배경

[014](./014-plan-approval-covers-protected-changes.md)~[018](./018-small-gaps-and-scope-view-idea.md)을 고친 뒤, 같은 방식(새 컨텍스트 에이전트 셋, 지시문이 가리키는 파일만 읽기)으로 세 번째 시뮬레이션을 돌렸다.

| 시나리오 | 확인된 것 |
| --- | --- |
| 빈 저장소 (습관 기록 앱) | 보호 대상은 골격 계획의 "게이트 설정" 행에서 맞춤. 판정 정지는 도입, 명세, 계획, 첫 확인의 4번이고, 원격 연결 질문이 하나 더 있음 |
| 기존 블로그 (회원가입·댓글·알림) | `pg` 설치, 마이그레이션, CI를 계획 칸으로 커밋하고 멈추지 않음. "post:" 커밋을 보고 도입 보고에서 `directPush`를 물음 |
| 도입된 상점 (쿠폰 요청) | 요구 대화 전에 "하지 않을 것"의 이유와 날짜를 알리고 물음. 기존 테스트 기대값 변경을 계획 칸으로 커밋함. 판정 전에 STATUS에 판정 대기를 씀 |

이번 시뮬레이션에서 드러난 [014](./014-plan-approval-covers-protected-changes.md)의 승인 순서 문장 오류와 [017](./017-direct-push-paths-and-deploy-rule.md)의 브랜치 보호 문제는 각 파일에 경위를 남기고 고쳤다.

## 결정

사용자가 AI 제안("다, 라는 작은 수정이라 고치고, 마는 기록한다")에 "그렇게 가자"로 동의했다.

- **기록 스크립트의 선행 파일**: `log-new.mjs`는 `STATUS.md`와 `docs/log/INDEX.md`(표 머리와 구분선)가 있어야 돈다. 없으면 예외를 낸다. 에이전트가 스크립트 코드를 읽고서야 알아냈으므로, SKILL.md 1절에 "도입의 첫 기록 전에 둘을 먼저 쓴다"를 넣었다.
- **두 부분 보고의 기록**: 제품 명세와 함께 보고하면 기록은 하나로 쓰고, 제목 끝에 `(제품 명세 포함)`을 붙인다.
- **골격의 확인 지점 위치**: CI 행이 확인 지점 뒤에 있어, CI가 기능 마감 전인지 후인지 애매했다. 확인 지점을 CI 행에 두어(첫 흐름은 자동) 확인 통과가 곧 골격 마감이 되게 했다.
- **묶인 "하지 않을 것"**: 추가하는 부분만 지우고 나머지는 남긴다.
- **`.gated-tdd.json` 기본값**: "기본값으로 둔다"가 "파일을 만들지 않는다"로도 읽혔다. 기본값 내용으로 만든다고 고쳤다.
- **새 clone**: `core.hooksPath`는 clone마다 켜야 한다. 채택 선언에 한 줄을 넣고, 세션 시작에서 장치가 있는데 훅이 꺼져 있으면 켜고 알린다.
- **판정이 아닌 질문**: 요구 대화나 원격 연결 질문으로 멈출 때도, STATUS.md가 있으면 "다음 할 일"에 `사용자 답 대기: <질문 요약>`을 쓴다. 빈 저장소의 맨 첫 질문은 STATUS가 아직 없어 예외다.
- **기존 제품의 인증 보호 경로**: 그 코드가 아직 없으면, 그 영역을 처음 만드는 기능의 계획에서 `.gated-tdd.json` 변경을 보호 대상 변경 칸에 적어 판정받는다. 블로그 에이전트가 스스로 택한 방식이고 014와 맞는다.

## 미룬 것

기능의 실제 내용에 관한 판단이라, 실제로 써 보며 정한다.

- 운영 DB 마이그레이션을 누가 언제 적용하는지. 플랫폼이 코드만 자동 배포하는 환경(Vercel)에서 미리보기 환경이 어느 DB를 쓰는지(운영 DB와 분리).
- "공개할 방법이 없는 반쪽 기능"의 기준. 회원가입만 먼저 병합하는 경우, 결제 없는 쿠폰처럼 사용자가 해볼 흐름은 있지만 제품으로는 덜 끝난 경우.
- 화면 배치 결정을 시안 비교(7절)로 할지 확인 지점(판정 질문 ④)으로 할지의 기준.
- 외부 계정 작업(DB 생성, 환경변수 등록)의 등급. ③(비용·비밀값)이면서 ④(실제 계정)이다.
- 요구 대화의 "열린 질문 먼저"와 `grill-me-plus` 호출의 관계, `grill-me-plus`가 남기는 기록과 `docs/spec`·`docs/decision`의 관계.

## 다시 볼 신호

- 위 미룬 항목이 실제 기능 개발에서 판단을 막거나 에이전트마다 다르게 처리된다.
- 새 clone에서 훅이 꺼진 채로 보호 대상 커밋이 들어간다.
