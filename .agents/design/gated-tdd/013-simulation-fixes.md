# 013. 새 컨텍스트 시뮬레이션으로 드러난 절차의 빈 곳을 고친다

- 날짜: 2026-10-16
- 상태: 채택
- 반영: skill-storage 1.7.0

## 배경

사용자 제안: 설계를 아는 에이전트가 확인하면 "처음 이 프로젝트에 접근한 AI가 잘 할 수 있는지" 알 수 없다. 그래서 서브 에이전트 셋을 만들어, 실제 개발 없이 이 스킬을 따르면 어떻게 진행할지 설명하게 했다. 폴더를 훑지 않고 지시문이 가리키는 파일만 읽도록 제한했다.

| 시나리오 | 결과 |
| --- | --- |
| 1. 빈 저장소에서 습관 기록 웹앱 | 초기 개발로 판단, `init-dev.md`를 열고 명세 전에는 짓지 않음. 첫 정지는 도입 결정 보고 |
| 2. 장치·명세 없는 2년 된 블로그에 기능 3개 | 표를 글자 그대로 따라 초기 개발로 분류. 골격이 맞지 않아 해석으로 메움 → [012](./012-requirements-for-every-change.md) |
| 3. 도입된 상점에 명세가 제외한 쿠폰 요청 | 기능 개발로 판단, 명세부터 고치는 결정 보고를 하고 멈춤 |

## 고친 것

이번 변경(1.7.0 초안)에서 생긴 문제:

1. **명세 커밋 시점 충돌** (세 에이전트 모두): `init-dev.md`의 "커밋한 뒤 보고"와 SKILL.md 5절의 "판정 → approve → 커밋"이 달랐다. 5절에 맞춰 "결정은 보고 전에 커밋하지 않는다"로 통일했다.
2. **기능 개발에 필요한 규칙이 `init-dev.md`에만 있었음**: 기능 지도 규칙과 명세 갱신 규칙을 `requirements.md`로 옮겼다. 계획 파일 이름을 `<기능 ID>`로 통일했다.
3. **유형 판별이 2절에 있는데 1절에서 필요했음**: 0절 6번으로 옮겼다.
4. **테스트 도구·CI 시점 불일치, 원격 없음, 기본 브랜치가 main이 아님**: `init-dev.md` 최소 도입에 넣었다.

원래부터 있던 빈 곳(사용자가 이번에 고치기로 함):

5. **유형을 보고에 밝히기**: 고른 유형과 근거를 첫 보고의 "내가 이해한 전제"에 쓴다. 신호가 겹치면 판정 질문 ①로 묻는다. 시뮬레이션 2만 스스로 했다.
6. **세션 시작 순서**: 도입 전에는 `budget.mjs`가 없으므로 복사 직후에 `start`한다.
7. **도입 승인 경계**: 도입 요청이 있으면 파일 준비는 묻지 않는다. 도입 커밋은 `.gated-tdd.json` 확정과 함께 결정 보고 한 번(`도입`)으로 받는다. "승인된 도입을 다시 묻지 않는다"와 "도입 커밋은 판정 후"가 부딪히던 것을 풀었다.
8. **브랜치 규칙**: 도입은 `chore/gated-tdd`, 기능은 요구부터 `feat/<기능 ID>`. 선행 기능이 병합 전이면 그 브랜치에서 분기하고 전제에 쓴다.
9. **행이 없는 결정의 ID**: `도입`, `SPEC-product`, `SPEC-<기능 ID>`. 결정 통과는 "스테이징 → approve → 커밋"으로 순서를 명시했다.
10. **계획이 없을 때 "계획 대비 위치"**: 절차상 위치와 기능 지도에서의 위치를 쓴다(`report-format.md`).
11. **예산 어댑터 안내 시점**: 도입 결정 보고에 한 번. Windows의 훅 실행 권한(`git update-index --chmod=+x`)도 적었다.
12. **AGENTS.md 이식 경로**: 도입할 때 SKILL.md 2~7절을 대상 저장소의 `AGENTS.md`에 옮겨 적던 것을 그만둔다.
    - 문제: 옮긴 글 속 `references/...` 경로가 대상 저장소에 없다. 0·1절이 빠진다. 스킬을 업데이트해도 사본은 낡는다.
    - 선택지: (1) 채택 선언과 저장소 값만 둔다(채택). (2) 스킬 사본을 `docs/guide/`에 복사한다. (3) 지금 방식에 경로만 고친다.
    - 사용자 반응: "어차피 AI가 skill을 auto calling 하는 거 아니야?" 자동 호출은 맞지만 description이 "저장소 규칙이 채택한 경우"로 좁혀져 있다. 그래서 그 근거가 되는 선언 한 줄이 항상 읽히는 `AGENTS.md`에 있어야 한다고 설명했고, (1)로 정했다.
    - `CLAUDE.md`는 `@AGENTS.md`를 둘째 줄에 두어 Claude Code가 선언을 읽게 한다.

## 버린 것과 미룬 것

- 스킬이 설치되지 않은 도구 지원: (1)을 고르면서 포기했다. Claude Code와 Codex는 스킬을 지원한다.
- 아직 고치지 않은 지적:
  - 사용자의 새 요청과 STATUS의 "다음 할 일" 중 무엇이 먼저인지
  - 도입 결정 보고에 명세 첫 질문을 붙일지 (시뮬레이션 1은 붙이지 않았고 2는 붙여 행동이 갈림)
  - Vercel처럼 배포가 Actions를 거치지 않을 때 "재사용 워크플로를 PR과 배포가 같이 쓴다"의 뜻
  - 기본값을 쓰는 오래된 STATUS의 처리
- 시나리오 3의 STATUS 불일치(최근 3건과 자동 진행 내역)는 시나리오를 만들 때 생긴 실수라 스킬 문제가 아니다.

## 다시 볼 신호

- 같은 방식의 시뮬레이션을 다시 돌렸을 때 에이전트들이 같은 지점에서 다르게 행동한다.
- 새 세션에서 에이전트가 `AGENTS.md`의 선언을 보고도 스킬을 부르지 않는다.
