## 무엇을 하나

`archify`는 아이디어, 계획, 또는 실제 코드베이스를 **탐색 가능한 독립 HTML 다이어그램**으로 만듭니다. 인라인 SVG, 다크/라이트 테마, 선택적 트레이스 모션을 담은 HTML 파일 하나를 결과물로 내놓고, 필요하면 PNG/JPEG/WebP/SVG/WebM로도 내보냅니다.

- 다이어그램 종류는 다섯 가지입니다: 아키텍처(구성 요소, 클라우드/보안/네트워크 토폴로지), 워크플로(승인 절차, CI/CD, 계획), 시퀀스(API 호출 체인, 요청 생명주기), 데이터플로(파이프라인, ETL/ELT, 데이터 계보), 라이프사이클(상태 전이, 재시도, 종료 상태). 휴가 계획이나 승인 절차 같은 일상 주제도 같은 다섯 타입으로 표현합니다.
- Mermaid의 `flowchart`/`graph`, `sequenceDiagram`, `stateDiagram` 입력을 읽어 토폴로지와 의미를 파악한 뒤, Mermaid 스타일을 그대로 베끼지 않고 Archify JSON으로 새로 그립니다.
- 실제 코드베이스를 그릴 때는 저장소를 뒤져 실제 동작의 근거를 찾고, 그 근거를 다이어그램에 출처로 남깁니다.
- 입력 JSON을 작성한 뒤 `node bin/archify.mjs finalize`를 실행해 검증, 전달, 엄격한 무결성 확인, 실제 브라우저 확인까지 한 번에 통과시킵니다. 게이트 중 하나라도 실패하면(종료 코드가 0이 아니면) 성공으로 보고하지 않고, 받은 진단으로 후보 JSON을 고쳐 다시 실행합니다.
- 작업마다 `.archify/<타입>-<슬러그>-<타임스탬프>/` 폴더를 새로 만들어 후보 JSON과 결과 HTML을 그 안에 둡니다. 나중에 요청이 와도 이전 결과물은 그대로 남습니다.

결과물: 작업 폴더의 HTML 파일(절대 경로로 보고), 다이어그램 타입, 검증 요약, 전달 영수증, 브라우저 확인 상태. 사용자가 시각 검토를 요청하지 않으면 실제로 눈으로 본 적 없는 "시각적으로 괜찮다"는 말은 하지 않습니다.

## 언제 쓰나

시스템 아키텍처, 인프라, 기술 워크플로, API 호출 시퀀스, 요청 생명주기, 데이터 파이프라인, 상태 머신을 그려야 할 때, 또는 Mermaid 다이어그램을 변환하거나 다듬어야 할 때 씁니다. 단계나 부분, 관계, 상태가 있는 일상 주제(휴가 계획, 신청·승인 절차, 돈이나 서류가 오가는 과정)에도 쓸 수 있습니다. 숫자 차트나 대시보드에는 쓰지 않습니다.

model-invoked라서 "아키텍처를 그려 줘", "이 흐름을 다이어그램으로", "Mermaid를 예쁘게 바꿔 줘" 같은 요청에 에이전트가 알아서 꺼내 씁니다. Node.js(18 이상)가 있어야 하고, 실제 브라우저 확인 게이트를 통과하려면 로컬에 Chrome이나 Chromium이 설치되어 있어야 합니다. 그 밖의 npm 설치는 필요 없습니다.

## 자주 묻는 질문

**왜 다이어그램 종류가 다섯 가지뿐인가요?**
아키텍처, 워크플로, 시퀀스, 데이터플로, 라이프사이클 다섯 타입이 구조·절차·대화·흐름·상태라는 서로 다른 모양을 덮습니다. 일상 주제도 같은 다섯 타입에 매핑해서 그리고, 아이콘과 범례만 그 주제에 맞게 고릅니다.

**`finalize`가 실패하면 처음부터 다시 만들어야 하나요?**
아닙니다. 실패한 게이트의 진단을 읽고 연결된 노드와 관계만 고쳐서 같은 `finalize` 명령을 다시 실행합니다. 후보 JSON과 출력 경로는 그대로 두고, 요청한 의미와 코드 근거를 보존한 채로 좁게 고칩니다.

**매번 새 폴더를 만드는 이유는요?**
같은 요청을 다시 손볼 때(복구 실행)는 같은 폴더를 재사용해야 하지만, 완전히 새로운 요청은 새 폴더를 받아야 이전 버전이 덮어써지지 않습니다.

**업데이트 알림이 뜨는데 무시해도 되나요?**
사용자가 명시적으로 묻지 않으면 에이전트가 먼저 설치나 업데이트를 하지는 않습니다. 다만 알림이 필요한 상황이면 응답에 한 줄로 안내합니다.

## 잘 되고 있다는 신호

- 결과 HTML 경로와 다이어그램 타입, 검증·전달·브라우저 확인 결과가 한 번에 보고됩니다.
- 실제 코드베이스를 그릴 때 다이어그램의 각 노드나 관계가 어떤 코드에서 나왔는지 추적할 수 있습니다.
- Mermaid를 넣었을 때 원본 스타일을 그대로 베끼지 않고 Archify 톤으로 새로 그려집니다.
- 실패한 `finalize` 실행 뒤에도 전체를 새로 그리지 않고 좁은 범위만 고쳐서 다시 통과합니다.
